# AI 助手模式 — 异步结果面板

## 背景

当前 AI 助手模式（Alt+Space）是同步流水线：

```
选中文本 → 录音 → ASR → LLM → 自动粘贴到焦点窗口
```

使用 Grok 4.2 Beta 等慢推理模型时，LLM 处理可能耗时 30 秒以上。用户不会干等，会切到其他窗口。结果回来后自动粘贴到"当前焦点窗口"会打乱用户操作。

### 核心矛盾

当前设计隐含假设：**"LLM 处理完时，用户还在原来的窗口"**。慢模型打破了这个假设。

## 目标

将 AI 助手模式的结果投递从"同步自动粘贴"改为"异步结果面板"，让用户在 LLM 完成后主动决定何时、何处粘贴。

## 需求

### R1: 结果预览浮窗

- AI 助手模式处理完成后，在一个独立的 always-on-top 浮窗中展示 LLM 输出
- 浮窗支持 **Markdown 渲染**（标题、列表、代码块、加粗/斜体、表格）
- 代码块支持**语法高亮**
- 浮窗可滚动、可调整大小
- 浮窗匹配现有设计系统（Anthropic 风格暖色调色板）
- 支持亮色/暗色主题

### R2: 操作按钮

- **「粘贴到原窗口」** — 恢复到发起请求时的窗口并粘贴（主操作）
- **「复制」** — 写入剪贴板，用户自行粘贴
- **「关闭」** — 丢弃结果，关闭浮窗
- 支持键盘快捷键：Enter = 粘贴到原窗口，Esc = 关闭（不覆盖 Ctrl+C，保留 WebView 原生文本选择复制）

### R3: 上下文信息展示

- 显示用户的语音指令（ASR 转写结果）
- 显示原始选中文本摘要（截断过长文本）
- 显示耗时信息（ASR 耗时、LLM 耗时）

### R4: 目标窗口记忆

- 发起请求时记录前台窗口句柄（HWND）— **已有实现，复用**
- "粘贴到原窗口"时通过 HWND 恢复焦点 — **已有实现，复用**
- 目标窗口已关闭时，优雅降级为"复制到剪贴板"

### R5: 剪贴板即时释放

- 捕获选中文本后**立即恢复**用户的原始剪贴板
- 不再将 ClipboardGuard 传递到整个 pipeline 末尾
- 选中文本存储在内存中，与剪贴板解耦

## 验收标准

- [ ] AC1: 使用 AI 助手模式后，结果面板浮窗自动弹出并展示 Markdown 渲染内容
- [ ] AC2: 点击"粘贴到原窗口"，焦点切回发起时的窗口，文本被正确插入/替换
- [ ] AC3: 点击"复制"，结果文本写入剪贴板
- [ ] AC4: 点击"关闭"或按 Esc，浮窗隐藏，结果丢弃
- [ ] AC5: Markdown 代码块有语法高亮
- [ ] AC6: 浮窗支持暗色主题
- [ ] AC7: 捕获选中文本后，用户的剪贴板立即恢复（不等到粘贴时才恢复）
- [ ] AC8: 目标窗口已关闭时，"粘贴到原窗口"降级为复制到剪贴板并提示

## 完成定义

- 所有 AC 通过
- 结果面板 UI 与现有主窗口设计风格一致
- 不影响听写模式（Normal Pipeline）的现有行为
- 不影响快速模型的使用体验

## 范围外

- LLM 流式响应（实时显示生成过程）— 作为后续优化
- 多个待处理结果的队列管理 — V1 仅支持单个结果
- 自动判断快/慢模型切换行为 — V1 统一走结果面板
- 结果面板的拖拽定位记忆

## 决策记录

### D1: AI 助手模式统一走结果面板（而非根据耗时自动切换）

**选择**: 统一使用结果面板

**理由**:
- 一致性优于自适应 — 用户不需要猜测"这次会自动粘贴还是弹窗"
- AI 助手的输出通常是 Markdown 格式，直接粘贴到目标应用会丢失格式信息
- 给用户审阅结果的机会 — 即使快速模型也可能输出不符预期的内容
- 实现更简单 — 不需要超时判断逻辑

**权衡**: 快速模型（< 3s）会多一步手动操作。可接受，因为 AI 助手模式本身就是需要审阅的场景。

### D2: 剪贴板即时释放

**选择**: 捕获选中文本后立即恢复剪贴板，选中文本存到内存

**理由**:
- 用户在等待期间可能需要正常使用剪贴板
- ClipboardGuard 长时间持有会导致后续复制操作被覆盖
- 更清晰的数据所有权 — 选中文本归 pipeline 管理，剪贴板归用户

### D3: Markdown 渲染方案选择 react-markdown

**选择**: `react-markdown` + `remark-gfm` + `react-syntax-highlighter`

**理由**:
- React 生态最成熟的 Markdown 方案
- 声明式组件，不需要 dangerouslySetInnerHTML
- GFM 扩展支持表格、任务列表、删除线
- 代码高亮通过组件组合实现，安全性好
- 桌面应用不需要过度关注包体积

## 技术约束（来自代码库研究）

- **HWND 已有捕获**: `on_start` 中已调用 `GetForegroundWindow()`，存储在 `target_window_start`
- **焦点恢复已有实现**: `win32_input::restore_focus_with_verify()` 支持 3 次重试
- **窗口无效检测**: `win32_input::is_window_valid()` 已实现
- **无 Markdown 库**: 前端当前未安装任何 Markdown 渲染库，需要新增
- **现有窗口模式**: NotificationWindow 提供了完整的参考实现（事件监听 + invoke + 自动隐藏）
- **设计系统**: Anthropic 风格调色板（ink/paper/sand/crail/steel/sage）+ Poppins/Noto Sans SC 字体
