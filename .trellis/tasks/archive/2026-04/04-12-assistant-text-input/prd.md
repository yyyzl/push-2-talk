# AI 助手结果面板 — 手动文本输入支持

## Goal

在 AI 助手结果面板（ResultPanelWindow）中添加文本输入能力，让用户可以直接打字追问，作为语音追问的补充通道。

## Background

当前 AI 助手模式的交互完全依赖语音：按热键→录音→ASR 转写→LLM 处理。上一个任务（04-11-assistant-followup-conversation）实现了多轮对话，但在 Out of Scope 中明确排除了键盘文字输入：

> 键盘文字输入追问 — 仅支持语音交互，不添加文本输入框

现在需要将其纳入支持。

## Current Implementation Analysis

### 后端已具备的能力
- `AssistantProcessor.process_followup()` 接收 `&str` 类型的 `new_instruction`，**不关心来源是 ASR 还是键盘**
- `ConversationSession` / `ConversationTurn` 结构是内容无关的
- 事件体系 (`TurnPendingPayload`, `TurnCompletePayload`, `TurnErrorPayload`) 内容无关
- `is_assistant_processing` 原子标志已实现并发保护

### 前端现状
- `ResultPanelWindow.tsx` 底部只有操作栏（关闭/复制全部/复制最新）
- 无任何输入框或文本提交机制
- 窗口配置：520×620, transparent, resizable, always-on-top, focusable

### 关键约束
- 结果面板是独立 Tauri 窗口（非 main window 内嵌）
- 面板 `focusable: true`，可以接收键盘输入
- 面板开 = 追问模式，面板关 = 新对话（已有设计规则）

## Requirements

### R1: 文本输入仅用于追问（面板已打开）

文本输入是语音追问的**补充通道**，不是替代。用户必须先通过语音发起一次新对话（面板打开），然后可以在面板内打字追问。

- 面板打开 = 有会话 → 输入框可用
- 面板关闭 = 无会话 → 无入口
- 不引入新的 UI 入口（无系统托盘菜单、无独立快捷键）

### R2: 语音与文本追问并行共存

两条路径互不干扰，结果等价：

| 用户动作 | 路径 | 效果 |
|---------|------|------|
| 面板打开时**按热键录音** | 语音追问（ASR → TNL → LLM） | 追加新轮次 |
| 面板输入框**打字发送** | 文本追问（直接 → LLM） | 追加新轮次 |

两者共享 `is_assistant_processing` 并发保护，同一时刻只能有一个在执行。

### R3: 输入区域 UI

在现有操作栏上方新增输入行：

```
┌──────────────────────────────┐
│ 🤖 AI 助手    [2 轮]     [×] │
├──────────────────────────────┤
│                              │
│   对话流区域 (可滚动)         │
│                              │
├──────────────────────────────┤
│ [输入追问...]          [⏎]   │  ← 新增
├──────────────────────────────┤
│  [关闭]  [复制全部]  [复制]   │  ← 现有操作栏不变
└──────────────────────────────┘
```

### R4: 输入交互规则

| 场景 | 行为 |
|------|------|
| Enter | 发送（非空时） |
| Shift+Enter | 换行 |
| 输入为空 | 发送按钮禁用 |
| LLM 处理中（语音或文本） | 输入框 + 按钮禁用 |
| Esc | 关闭面板（即使输入框聚焦） |
| 面板首次打开 | 输入框**不自动聚焦** |

### R5: 耗时信息自适应显示

- `asr_time_ms > 0`（语音轮次）：显示 "ASR x.xs · LLM x.xs · 总计 x.xs"（不变）
- `asr_time_ms = 0`（文本轮次）：只显示 "LLM x.xs"

## Acceptance Criteria

- [ ] 语音新对话后，面板底部出现输入框
- [ ] 输入框输入文本 + Enter → 追加新轮次（用户气泡 + AI 回复）
- [ ] Shift+Enter → 换行，不发送
- [ ] 空内容 → 发送按钮禁用
- [ ] LLM 处理中 → 输入框和按钮禁用
- [ ] LLM 处理中按语音热键 → 被拒绝（并发保护）
- [ ] 打字追问期间按语音热键 → 被拒绝（并发保护）
- [ ] Esc 在输入框聚焦时仍能关闭面板
- [ ] 文本轮次耗时只显示 "LLM x.xs"
- [ ] 语音轮次耗时显示不变（"ASR · LLM · 总计"）
- [ ] LLM 失败 → 错误气泡 → 可再次打字重试
- [ ] 面板首次打开 → 输入框不自动聚焦
- [ ] 语音追问流程无任何退化

## Definition of Done

- 所有 Acceptance Criteria 通过
- 手动测试覆盖：语音开头→打字追问、打字中按热键被拒、错误重试、Esc 关闭
- 不需要新增自动化测试（核心逻辑 `process_followup` 已有测试覆盖）

## Out of Scope

- 纯文本新对话（不通过语音，从零开始打字）— 需要新入口，留作后续迭代
- 文本追问携带选中文本 — 面板内打字场景不涉及外部选中文本
- 输入历史记忆 / 自动补全
- 流式响应（Streaming）

## Decision Notes

### DN1: 方案选择 — 仅追问 vs 完整替代

**选择方案 A：仅追问。** 理由：
1. 实现成本极低 — 只需在现有面板加输入框 + 一个新 IPC 命令
2. 覆盖最高频场景 — 语音开头 → 打字继续
3. 不需要新 UI 入口
4. 方案 A 是方案 B（完整替代）的子集，后续可无痛扩展
