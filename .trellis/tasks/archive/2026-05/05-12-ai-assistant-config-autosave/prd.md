# 修复 AI 助手配置入口与自动保存

## Goal

补齐 AI 助手页和原型图之间的配置体验差异，让用户能在当前页面看到并配置联网搜索 API，同时确保问答模式提示词、文本处理提示词的编辑会自动保存，不需要用户额外催促或手动找隐藏入口。

## What I already know

* 用户指出当前 AI 助手页的 `LLM 连接配置` 和 `联网搜索` 区域没有给出联网 API 配置入口。
* 用户进一步指出提示词区域需要确认自动保存能力。
* 原型图中 AI 助手页至少包含：LLM 当前模型卡片、可更换模型入口、联网搜索说明、问答模式提示词、文本处理提示词。
* 当前仓库已有联网搜索相关提交，可能存在后端或配置模型，但前端入口/状态可能没有完整呈现。

## Assumptions

* 不新增全新设计系统，优先沿用当前米白色后台工具风格和原型图布局。
* 若已有联网搜索配置字段和保存命令，优先复用；若缺少前端绑定，则补齐最小必要 UI 和保存逻辑。
* 提示词自动保存使用现有配置保存机制，不引入额外持久化通道。

## Requirements

* AI 助手页必须提供可见的联网搜索 API 配置入口，而不是只显示说明文案。
* 未配置联网搜索 API 时，页面只展示未配置状态和配置入口；启用开关、搜索参数和文本模式等详细设置先折叠/隐藏。
* 已配置可用搜索引擎后，再展示联网搜索启用入口，并将高级参数放在可展开区域中。
* 高级参数折叠控制使用紧凑的 Chevron 图标按钮表达展开/收起，不使用突兀的“展开设置/收起设置”文字按钮。
* 联网搜索配置区应展示启用状态、服务商/API 端点/API Key 等必要配置项，状态清晰可感知。
* 搜索 API 配置抽屉应采用成熟设置页形态：左侧为 provider 列表/状态，右侧为当前 provider 的详情表单；添加 provider 使用紧凑模板入口，避免点加号后在下面不断堆卡片。
* 配置抽屉空状态应先引导选择一个搜索服务商模板；新增后自动选中该 provider 并在右侧编辑详情。
* 搜索 API 配置抽屉里必须能明确设置任意已配置 provider 为默认搜索引擎；用户点击“默认”后不应被自动纠正逻辑抢回原 provider。
* 如果用户把已配置但未启用的 provider 设为默认，应自动启用该 provider，避免“默认但不可运行”的状态。
* 联网搜索 API 的连接测试反馈必须和 LLM 模型配置测试反馈保持一致：成功时显示清晰的绿色成功标识/状态，而不是只有朴素文本。
* 联网搜索结果展示需要重新打磨视觉层级，避免大面积土气蓝色和过扁平的信息块；“搜索到 N 个词条/结果”的状态表达应更精致、克制、可扫描。
* AI 语音助手默认进入时，如果配置中已经启用联网搜索且默认搜索引擎可用，应保持联网开启状态，不应回到关闭。
* AI 助手执行过程中即使某次回复没有实际调用联网搜索工具，也不应自动关闭用户配置的联网搜索开关。
* LLM 配置卡片对齐原型图：显示当前模型、架构/模型名、API 端点，并提供更换入口。
* 问答模式提示词和文本处理提示词编辑后自动保存。
* 自动保存需要有防抖，避免每次按键都立即写配置。
* 自动保存应有基础状态反馈：保存中、已保存或保存失败；空闲时不常驻显示突兀的“自动保存”胶囊。
* 对照 prototype 中 AI 助手页相关 mockup，补齐明显遗漏的交互或文案。

## Acceptance Criteria

* [ ] 用户能在 AI 助手页直接配置联网搜索 API，不需要跳到隐藏入口或猜配置位置。
* [ ] 未配置搜索 API 时，AI 助手页不铺开联网搜索高级参数，只显示清晰的配置 CTA。
* [ ] 配置搜索 API 后，用户能看到启用入口，并按需展开高级参数。
* [ ] 高级参数入口是 Chevron 图标按钮，交互清楚且不占用主操作层级。
* [ ] API 配置抽屉不是卡片堆叠式；新增 provider 后进入单项详情编辑，列表区可快速切换 provider。
* [ ] 在 API 配置抽屉中，用户能把其他已配置搜索引擎设为默认，且选择会被保留。
* [ ] 联网搜索 API 测试成功后有绿色成功状态，风格和 LLM 连接测试反馈一致。
* [ ] 联网搜索结果区域视觉更克制精致，结果数量与条目展示不再依赖突兀蓝色块。
* [ ] 已启用并配置可用搜索引擎后，AI 助手默认带联网能力进入。
* [ ] 单次 AI 助手回复未使用搜索工具时，不会把联网搜索配置自动改成关闭。
* [ ] 联网搜索开关和 API 配置修改后能持久化，刷新/重开后仍然保留。
* [ ] 两个提示词 textarea 修改后自动保存，刷新后显示最后保存值。
* [ ] 保存失败时页面有可见提示，不静默丢失。
* [ ] 页面视觉结构与原型图主要区域一致，且没有重叠、截断或不可点击控件。
* [ ] 相关最小测试或构建检查通过。

## Definition of Done

* 修改前完成 GitNexus impact 分析并记录风险。
* 遵循现有 React/TypeScript 和 Tailwind 风格。
* 运行与变更相关的最小测试或构建检查。
* 如果无法完整验证，说明原因和剩余风险。

## Technical Approach

1. 对照 `prototype/src/mockups/AssistantPageMockup.tsx` 与 `src/pages/AssistantPage.tsx`，列出差异。
2. 查找联网搜索配置和提示词在 config 类型、保存上下文、页面组件中的现有实现。
3. 复用已有配置保存机制补齐联网 API 配置 UI 和提示词防抖自动保存。
4. 用最小测试/构建验证 TypeScript 类型和保存路径。

## Out of Scope

* 不更换全局导航或整套视觉语言。
* 不新增实际第三方搜索后端能力，除非当前后端已具备字段但未暴露。
* 不处理与 AI 助手页无关的页面改版。
