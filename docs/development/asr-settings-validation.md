# ASR 设置与统一下拉控件验收

2026-09-28，分支 `codex/platform-integration`。本轮解决旧 Mac 测试包与集成代码不一致、ASR 主备概念混淆，以及系统原生下拉样式不统一的问题。

## 行为约定

- 千问模型来自前后端共用的 `src/shared/qwen-models.json`：录音识别 5 个、实时识别 6 个。两个模式独立保存。旧配置缺少模型字段时继续使用原来的 profile，不自动升级模型。
- 模型选项展示名称与完整 ID；未知的已保存值仍然可见，不在打开页面时写回默认值。
- 主服务与备用识别分开。千问/豆包目前支持硅基流动作为额外备用，只有一个服务时展示名称，不制造单选项下拉。HTTP 路径会并行请求，优先采用主服务结果，页面明确提示可能分别计费。
- 豆包输入法的实时失败回退支持硅基流动、千问和豆包的 HTTP 客户端；备用千问只配置 HTTP 模型。
- 关闭备用只关闭开关，保留服务与凭据。听写和助手的共同回退入口必须检查开关，关闭后不能把录音发给已保存的备用服务。
- 不受支持的旧主备组合保留原值并提示；只有用户点击“改用…”才替换。硅基流动作为主服务时不新增额外备用。
- 设置页、主页侧栏、LLM 绑定、润色预设、思考模式和词库分类共用 `Select`；`ConfigSelect` 只负责即时保存反馈。底层使用 [Radix Select](https://www.radix-ui.com/primitives/docs/components/select) 处理焦点、键盘、滚动和弹层定位。
- 空字符串仍表示“跟随默认”；禁用项不可选。保存失败保留草稿，统一错误提示提供“重试保存”。

## Mac 安装包实机检查

普通 debug `.app` 已构建并通过签名完整性检查，安装在 `~/Applications/PushToTalk.app`，没有启用 ATDD 浮动测试面板。原先运行的是旧 `macos-platform` 工作树的包，因此此前看不到集成分支的多模型选择。

实机已展开 5 项录音模型和 6 项实时模型，验证 Escape 关闭并归还焦点。已有配置和凭据在本机备份后逐字段比较保留；旧模型继续显示 Qwen3。空 Key 配置可能触发现有的自动切换服务保护，这次查看后已恢复原来的服务选择，未填写或修改真实 Key。

新 ad-hoc 签名需要重新获得 macOS 隐私授权，当前包保持停止服务状态；本轮没有把界面检查当成新包的录音/云端验收。此限制不影响上述合成配置自动化用例。

## Windows 补充验收

本次代码晚于 [Windows 架构交接](windows-validation-handoff.md) 中 `ac90c5c` 的旧产物。请取集成分支最新 SHA，记录它并重新构建，或下载与新 SHA 对应的 CI 产物。旧产物不包含本轮 UI 改动。

1. 从线上 v1.6.1 覆盖升级，保持主服务、旧模型、API Key、热键、LLM 绑定与词库不变；首次打开设置页不触发改配。
2. 打开千问两种模型列表，验证 5 / 6 个选项；选择新模型后重启，确认两种选择独立保存。
3. 用鼠标与键盘操作 ASR、LLM 默认/继承、润色预设、思考模式、词库分类；检查 Escape、方向键、首字母定位、禁用状态、长名称与小窗口。
4. 在词库修改分类，不应同时选中/取消选中父词条。停用润色或运行服务时，下拉禁用行为应保持。
5. 主服务千问/豆包：开启备用需配置硅基流动；关闭再开启保留服务与凭据。保留不支持的旧组合，不应静默重写。
6. 豆包输入法：人为制造实时服务失败，分别验证备用开启/关闭。关闭时不得调用已保存的备用服务；开启时按所选 HTTP 服务回退。听写与助手都需要验证。
7. 操作过程中若写盘失败，页面保留选择并可重试；重试后重启仍保留用户选择。

Windows 实机结果由 Windows 任务填写，不以 Mac 的界面和编译证据代替。
