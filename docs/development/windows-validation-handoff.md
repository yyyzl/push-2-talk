## 3. Windows 执行环境与取代码

优先使用有快照的 Windows 虚拟机或专用测试电脑，并确认麦克风输入、音频输出和桌面交互实际可用。至少记录 Windows 版本/构建号、x64/ARM64、物理机/虚拟机、应用权限级别、麦克风及目标编辑器版本。先完成手边环境可执行的项目；另一 Windows 版本未测须如实记录，不能把 Windows 11 或 CI Windows Server 的结果写成 Windows 10 已通过。

使用独立检出保留 Windows 端正在开发的内容。下面命令在已有仓库的 PowerShell 中执行；路径/分支已存在时，核查后复用，不强制删除或重置：

```powershell
git status --short
git fetch origin
git worktree add -b codex/windows-validation ../push-2-talk-windows-validation origin/codex/platform-integration
Set-Location ../push-2-talk-windows-validation
git rev-parse HEAD
git merge-base --is-ancestor ac90c5c84adc4c0d78f407a8951f3307c93a8f80 HEAD

```

祖先检查应返回 0。最后一条如果出现业务代码改动，先确认被测版本，不能直接引用旧 CI 的通过结论。未修改代码时可复用已有自动化证据，把精力放在实机缺口上；修复代码后必须重跑相关测试及两端 CI。

### 取安装包

CI 下载需要有 GitHub 访问权限：

```powershell
gh run download 36404615223 --repo yyyzl/push-2-talk `
  --name prototype-windows-latest-ac90c5c84adc4c0d78f407a8951f3307c93a8f80 `
  --dir ../ptt-windows-validation-artifacts
Get-ChildItem ../ptt-windows-validation-artifacts -Recurse -Filter *.exe |
  Get-FileHash -Algorithm SHA256
```

这是 **debug NSIS 原型包**，产物设置保留 7 天，本次查询的到期时间为 2026-10-05 09:45 UTC。如果过期，用同一个 SHA 在 Windows 本地重新构建，记录编译模式和安装包 SHA256，不能用同名的其他版本顶替。

需要本地构建时，使用 Windows 原生 Node.js 22、Rust stable/MSVC、C++ Build Tools、CMake 和 WebView2 环境；按仓库实际提示补齐依赖。逐条执行，任何命令失败都先处理，不能继续把后续结果当成全通过：

```powershell
$env:CMAKE_POLICY_VERSION_MINIMUM = "3.5"
npm.cmd ci
npm.cmd run test:ts
npx.cmd playwright install chromium
npm.cmd run test:ui
npm.cmd run build
cargo check --locked --manifest-path src-tauri/Cargo.toml
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm.cmd run tauri build -- --debug --ci --bundles nsis --config .github/tauri.prototype.conf.json -- --locked
```

本地 debug 安装包位于 `src-tauri/target/debug/bundle/nsis/`。准备发布前还应去掉 `--debug` 构建 release NSIS，并对该包重复升级及录音/回填冒烟；release 输出为 `src-tauri/target/release/bundle/nsis/`。Windows 不运行 `scripts/build-macos-atdd.sh` 或 Mac 专用 ATDD 驱动。

### 自动更新的验收边界

`.github/tauri.prototype.conf.json` 关闭了 updater 产物生成。**手动运行 NSIS 覆盖安装通过，不等于应用内“点击升级”通过。** 应用内升级需要按正式发布方式签名的候选包及隔离更新源，检查下载、签名校验、退出、安装和重启全过程。没有这个环境时，把 `UPD-01` 记为阻塞/未测；不要修改线上 `latest.json`、发布正式版本或替换用户的生产更新源来完成本轮测试。

## 4. 旧配置与数据准备

优先选择一份在 v1.6.1 上确认可用的真实配置副本；使用用户已提供的测试凭据即可，不要求用户重新录入。真实配置只保存在本机私有测试位置，不提交到 Git、Issue 或测试报告。

1. 在隔离环境安装并启动 **v1.6.1**。先确认原有 ASR、LLM、快捷键和词库能工作，记录一次成功听写/回填作为对照。若旧版本身已因额度、网络、Key 失效而不可用，先标记环境阻塞，不能归咎于升级或换模型掩盖。
2. 完全退出托盘程序，确认进程已结束，再做虚拟机快照/备份。至少备份整个 `%APPDATA%\PushToTalk\`，不能只复制 `config.json`。已存在的 `personalization\user_terms.db`、SQLite 伴随文件和 `correction_pairs.json` 都要保留。WebView 本地历史、安装信息及自启状态也属于环境快照范围。
3. 在报告中只记录字段“保留/改变/缺失”。Key、Token、Endpoint 中的认证信息、私人词条和历史正文必须脱敏；不要把完整配置/请求头写入日志。
4. 在同一个隔离账户、同一安装范围和路径上，运行候选 NSIS **直接覆盖安装**。不先卸载、不删配置、不导入默认配置、不先手动修配置。
5. 新版首次启动后先执行 `UPG-01` 至 `UPG-04`，这一轮通过前不要重新选择模型或补 Key。

仅修改 `$env:APPDATA` 不能作为“已经隔离”的证据，原生目录 API、WebView 和系统设置可能仍指向其他位置。确认实际读写目录；使用正常测试账户路径或虚拟机快照。

仓库 `tests/fixtures/config/v1.6.1.json` 使用假 Key 和 `.invalid` 地址，适合无网络迁移/损坏测试，**不能用于证明真实识别或真实助手成功**。新安装和损坏文件测试用另外的干净快照，避免污染升级对照组。

### 比较准则

允许新增结构字段、补齐元数据和必要的幂等迁移；不要求 JSON 字节完全相同。必须保持用户原有语义：

- ASR 主/备用提供方、备用开关、凭据、语言、实时/非实时模式与旧模型的实际选择。v1.6.1 没有 `qwen_profile` 的配置应保持原 Qwen3 路径，不能被升级自动切到 Audio 3.1。
- 润色、助手、学习各自最终解析出的 Endpoint、Key、Model；原提示词逐字保留，包括空字符串、换行和空预设列表。字段搬迁后只看旧字段有值还不够，要确认实际请求用了正确配置。
- 双快捷键、按住/松手模式、关闭行为、主题、静音和已有功能开关。
- 词库内容、删除状态和个性化数据。旧配置缺少的新增强字段采用兼容关闭值，不能因为打开设置页就自动启用。
- 新配置已经明确选择的模型/开关，经修改其他设置和重启后仍保留。

每个用例填写 `通过 / 失败 / 阻塞 / 未测`。看到设置页正常不代表识别链路通过；“阻塞/未测”不计为通过。

### P0：升级与数据安全，失败即阻止合入

| ID | 执行步骤 | 通过标准 |
| --- | --- | --- |
| UPG-01 | 按第 4 节从 v1.6.1 原位覆盖安装；首次启动不编辑任何设置 | 应用可启动；旧 Key、提供方、模型、提示词、快捷键和词库仍可用；不要求重新配置 |
| UPG-02 | 使用原快捷键、原 ASR，向记事本听写固定句子；再到浏览器输入框重复；各 3 次 | 实际识别并回填，每轮只插入一次；无静默换服务/模型。先与旧版对照，措辞微差不能代替路由、凭据和原行为的核查 |
| UPG-03 | 原配置启用了润色/助手时，分别跑一次真实润色、无选区问答、有选区处理并插入结果 | 各功能沿用原连接、模型与提示词；选区处理不丢正文、不插错位置；未配置的功能不能靠临时新 Key 冒充升级成功 |
| UPG-04 | 退出并重开两次；只改主题再保存、重启；按第 4 节比较配置 | 与用户操作无关的设置、有效凭据及词库没有变化；迁移不会反复重置选择 |
| CFG-01 | 在主窗口编辑一个字段，同时用托盘切换另一个字段；连续执行 5 轮，重启核查 | 两处最终选择均保留，没有旧整份快照覆盖后台新值；同一字段的最终结果按实际操作顺序核查 |
| CFG-02 | 用专用测试目录制造可确认的写入失败；分别改模型、API Key、开关；恢复写权限后点“重试保存” | 错误可见；编辑内容保留；无需重输；恢复后保存并实际生效；无无休止自动重试。只针对测试目录操作，记录并恢复原权限；“设只读”但未真正写失败不算覆盖 |
| CFG-03 | 在独立快照中放入损坏 JSON；启动并等待超过自动保存延时，再重启 | 显示读取错误；不能用默认值覆盖原文件。比较文件字节，确认 Key/配置未被静默清空 |
| CFG-04 | 独立快照：有效 `config.json.bak` + 缺失主文件；另测损坏主文件 + 有效备份 | 主文件缺失时可恢复；主文件存在但损坏时不能悄悄用旧备份掩盖问题 |
| DICT-01 | 从旧 JSON 词库升级；增词、删词、删除最后一个词，分别重启；再改主题和 ASR 选择 | SQLite 和页面一致；被删除词条不会被旧 JSON 快照复活；普通配置保存不把运行时热词写成私人词库 |
| REC-01 | 原按住录音快捷键：正常录音 3 次；极短按下/松开重复 10 次；开始时重复触发 | 每轮最多一个会话、一次完成；短录音成功或明确结束都可，不能卡住、晚到启动或混入上一轮文本；随后正常录音仍成功 |
| REC-02 | 分别在启动、录音、识别/助手处理阶段取消；等待原请求返回，再开始新录音 | 取消后的结果不再回填、不串到下一轮；录音资源释放；无新录音时麦克风占用结束，下一次可以成功 |
| INPUT-01 | 录音后切换窗口/浏览器标签；等待处理时关闭原目标；另测两个同名文档 | 只允许回到可确认的原目标，或明确提示/保留结果供手动处理；不能把文本发到新焦点、错误标签或同名替代窗口 |
| MUTE-01 | 先播放音频并记录各应用音量/静音状态；开启“静音其他应用”，测试成功、取消、识别失败、退出服务 | 所有分支都恢复之前的状态；原来就静音的应用不能被强制解除静音；本轮失败后下一轮仍正常 |

固定测试句建议使用“今天验证语音输入，编号一二三四五，请保留 TypeScript 和 OpenAI。”，仅在专用测试文档中输入。测试文本可公开，真实私人内容不可作为证据上传。

### P1：原生功能和故障恢复，影响原有使用同样阻止合入

| ID | 执行步骤 | 通过标准 |
| --- | --- | --- |
| KEY-01 | 验证已有自定义键、按住模式、松手模式（包括实际配置的 F2）；长按自动重复、改快捷键、重新启动服务 | 无重复触发/幽灵按键；松手/取消/完成动作正确；看门狗恢复后下一次能录音；保留旧权限级别要求 |

| ASR-03 | 配置允许 fallback 时，让主服务发生可复现失败，再测关闭 fallback 的同一场景 | 与配置允许的行为一致；成功结果最多回填一次；明确的认证/额度错误不能被当作“兼容性通过”隐藏 |
| INPUT-02 | 记事本、实际浏览器输入框、VS Code；中文输入法开启；多行选区；剪贴板原有文本，随后主动复制新内容 | UIA/剪贴板路径不会贴到错误控件、重复粘贴或把测试前旧剪贴板覆盖用户之后的新复制；100/150ms 时序保护不被移除 |
| ASSIST-01 | 无选区问答、有选区处理、结果面板文字追问各一轮；处理中取消再发新问题；复制/插入回复 | 模式和选区正确；多轮状态正确；旧任务的流式片段和结束事件不会覆盖新轮次 |
| LIFE-01 | 录音/处理时托盘退出；识别失败后重启服务；拔掉/恢复麦克风后重新录音，各重复 3 次 | 无残留任务和持续占用；失败可见、资源可恢复；后续正常流程可用；不能因退出丢失配置 |
| CFG-05 | 正常使用中停留各设置页至少 30 秒；操作托盘开关；慢启动时立即输入 Key 并等待初始化结束 | 不发生无操作的保存循环；慢启动输入被保留，初始化完成后保存并用于实际请求；无旧启动配置覆盖新编辑 |
| NEW-01 | 另一个干净快照全新安装候选包；启动默认流程，再主动配置模型、热键和词库后重启 | 新安装默认值可用；初始化不会写坏文件；用户明确保存的新选择不被旧配置兼容逻辑改回 |
| SHELL-01 | 托盘隐藏/显示、关闭行为记忆、自启开关、任务栏/托盘图标、结果和录音窗口 | 行为与设置一致；不会启动双实例或遗留遮挡窗口；测试后恢复测试环境的自启状态 |

针对低频竞态，使用可恢复的测试延迟或本地模拟响应把窗口拉长，记录注入方式及移除后的正常冒烟结果；不能只依靠“手快点几次”宣称覆盖了晚到响应。

## 6. 发现问题后的处理顺序

1. 先保存脱敏复现步骤、用例 ID、被测 SHA、实际行为、预期行为和证据，区分旧版已有问题、集成回归、额度/网络/设备阻塞。
2. 在 `codex/windows-validation` 上修复，不修改 `main` 或把旧 Windows 分支整块重新覆盖进来。先补能够稳定失败的测试，确认失败后修复，再让同一个测试通过。
3. 平台问题优先修 `src-tauri/src/platform/windows/`；共享配置/会话问题在相应服务层修复。保留 Mac 实现、工厂接口、原生时序保护和其他用户设置，不以清空配置、关闭功能或默认换模型作为修复。
4. 修复后复验失败用例、`UPG-01` 至 `UPG-04`、正常录音/取消/下一轮恢复，并跑相关自动化及 Windows/macOS CI。最终报告必须对应最后修复后的 SHA，旧测试结果不能自动沿用。
5. 可以在验证分支提交并推送修复和报告，供集成审查；不要直接合入 main、发布 Release、修改正式更新源或重引入已删除的 GitNexus/Trellis。

执行者应自己操作并核验界面与结果。只有受保护的 UAC/登录、无法取得的凭据或设备条件需要用户介入，并明确具体缺什么。不要把已具备自动化/桌面操作能力的测试再交回用户手工完成。
