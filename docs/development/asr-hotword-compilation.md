# ASR 热词编译契约

现行入口是 `compile_asr_pack_with_correction_pairs`，实现位于
`src-tauri/src/personalization/hotword_compiler.rs`。HTTP、实时识别及回退路径复用同一编译器，提供方只负责输出协议格式。

## 输入、排序与载荷

- 兼容普通 `word` 和 `word|source|category` 词条，只把第一个片段中的纯词发送给 ASR。
- 跳过空词，忽略大小写去重；同词保留更高优先级来源，同优先级保持首次出现顺序。
- 来源顺序：手动词库 > 已确认纠错对 > 最近历史 > 当前窗口 > 自动学习 > 已选领域 > 内置兜底词。
- 纠错对只采用已启用且非空的 `corrected_text`。原词与别名不进入当前提供方载荷。
- 排序后按提供方上限截断；排序权重是本地优先级，不等于提供方请求权重。

| 提供方 | 上限 | 对外格式 |
| --- | --- | --- |
| Qwen3 legacy HTTP / Realtime | 50 | 纯词以 `、` 拼接成 corpus 文本 |
| Qwen Audio 3.1 / 3.0 HTTP / Realtime | 50 | `vocabulary` 对象，纯词作为键，每词固定权重 `4` |
| Doubao HTTP / Realtime | 100 | `{"word":"纯词"}` 数组，不额外发送权重 |

空词库沿用各提供方原有的省略字段行为；不能为清理内部结构而改变已工作的请求协议。

## 运行时与配置边界

`start_app` 加载纠错对快照，接受学习结果后刷新；HTTP 和实时会话消费内存快照，不在构造请求或发送音频块时读磁盘。文件缺失或损坏时降级为空快照，不能阻断录音。

上下文热词是可选的实验功能，默认关闭，旧配置中显式启用的值予以保留。开启后，从近 24 小时成功记录和当前目标窗口提取有限数量的技术词；读取失败、空文本等情况退回原词库。窗口读取经过平台接口，不能直接假定所有平台都有 Windows UIA。

历史和窗口来源的词只参与运行时词库快照，不写入用户词库或持久化 `dictionary`。上下文读取不能输出完整原文到日志。偏好设置中的开关在停止服务后调整，下次启动生效。

## 清理边界与验证

没有生产消费者的 `TnlDictionaryPack`、`LlmContextPack` 及对应编译接口已删除；无纠错对的调用直接传 `&[]`，不再保留重复包装函数。ASR 编译、渲染、纠错对缓存和本地 TNL 实际处理路径保留。

必须覆盖：纯词提取、来源排序、去重、截断、空词库、禁用纠错对，以及所有提供方载荷的兼容测试。前端测试还需验证运行时词条不被保存成用户词条。涉及生产路径时运行完整 Rust 测试及 `cargo check`。
