## 已复现并修复

| 问题 | 修复后的行为 |
|---|---|
| main 没有 `qwen_profile`，升级被自动切到 Audio 3.1 | 原用户保持 Qwen3；新安装与升级分别处理 |
| 新字段解析失败时，用默认配置替换大部分旧字段 | 返回可见错误并保留文件；禁止静默丢失凭据和配置 |
| 最早根级 API Key 迁移后仍选中豆包输入法 | 恢复原 Qwen 服务；只有 SiliconFlow Key 时使用 SenseVoice |
| 旧原子写入移动原文件后中断，启动忽略 `.json.bak` | 原文件缺失时恢复备份；损坏的原文件不被旧备份覆盖 |
| 保存到异常目录时移动了目标目录 | 先拒绝目录；写独立临时文件并使用平台原子替换 |
| 主模型 SenseVoice 残留实时标记，误用千问接口 | 按服务商能力确定传输方式，SenseVoice 使用自身 HTTP 接口 |
| localStorage 迁移未计入豆包输入法凭据 | 任意已保存的后端 ASR 凭据都会阻止旧缓存覆盖 |
| 旧 TNL 缺失新字段，自动开启口语清洗 | 保持 `off`；明确选择的新模式保留 |
| 加载时恢复了用户主动清空的预设列表，或整块重置助手配置 | 保留空预设；仅补全缺失提示词，不覆盖其他配置 |
| Qwen3 实时发送 `language: auto` 被云端拒绝 | 自动语言省略该字段；中文继续发送 `zh` |
| 选择器在连续修改后保存失败，回滚到更早的值 | 回滚到本次修改前的值 |

## 严格保留旧行为复查（2026-09-28）

验收原则：升级可补充结构，但不能替用户更换服务、模型、提示词或开启新的文本增强。新安装使用新默认值；现存文件缺失新增字段时使用兼容值。已经明确保存的新模型与开关不回退。

本轮先写并运行失败测试，再修复以下问题：

- 停止把旧版默认助手提示词自动替换为新的选区上下文提示词。旧后端默认、旧前端默认、自定义、空字符串和 CRLF 均原样保留；旧文件缺失整段助手配置或提示词时补旧默认。新安装仍用新默认。
- 旧配置缺失精确纠错、音节纠错开关时保持关闭，即使整个 `tnl_config` 不存在也一样。测试实际运行带既存纠错对的个性化引擎，确认不会修改原文本或生成待仲裁候选。
- 新增 `tnl_config.enable_personalization_hotwords` 与 `enable_context_hotwords` 兼容开关，分别控制纠错对 ASR 热词、当前输入窗口与近期历史 ASR 热词。旧文件缺失时均为 false，新安装为 true。关闭时不读窗口上下文、不追加近期历史热词，也不载入纠错对热词。高级热词开关目前保留在配置层，尚无独立设置页控件。
- 重写早期 shared 配置向 Provider Registry 的迁移：先解析每个功能的真实连接，再迁移。测试润色、助手、学习共享/独立模式的 8 种组合，逐一核对 endpoint/API key/model，并验证保存后再次加载。独立连接保留，多个功能可共用服务商而使用不同模型。
- 早期 `learning_config.llm_endpoint` 迁移同时保留继承的密钥和模型，避免迁移后留下空认证或空模型。
- 已明确保存的双快捷键优先于残留的旧单快捷键，即使双快捷键恰好等于默认值也不被覆盖。
- 助手流式入口兼容旧接口返回的普通 JSON；明确拒绝 stream 的 400/422/501 可用相同 endpoint/key/model/messages 重试一次非流式请求。认证、额度、网络、通用服务端错误与已经产生的部分输出不重试、不换模型。JSON 中的 tool calls 保留，错误对象不能伪装成功空回答。
- 流式解析缓存跨网络分片的 UTF-8 字节，避免中文和 emoji 被拆成乱码。

### 启动自动保存保护

补充复查发现：初始化开始时就把“已加载”标记设为 true，会让自动保存计时器在旧配置尚未返回时工作。现在分开记录“正在加载”和“成功加载”：只有加载成功后才允许自动保存与运行时更新；保存计时器真正执行时再次检查加载状态与同步窗口。加载失败保持禁止写回，重复渲染不会并发加载。

新增可控延迟测试覆盖慢加载期间计时器到期、外部同步窗口提前结束、重复初始化、失败与重试。最终前端测试为 **163 项通过**，构建通过。Rust 本轮仍为 **571 项通过、8 项忽略**，没有因这个前端补充而变更 Rust 实现。
