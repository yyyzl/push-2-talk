# ASR 与配置升级验收（2026-09-28）

范围：`codex/platform-integration`，在已合并的 Windows 与 macOS 实现上修复历史配置兼容和千问模型选择。没有合入 main，也没有替换本机已授权的应用。

## 已复现并修复

| 问题 | 修复后的行为 |
|---|---|
| main 没有 `qwen_profile`，升级被自动切到 Audio 3.1 | 原用户保持 Qwen3；新安装与升级分别处理 |
| 新字段解析失败时，用默认配置替换大部分旧字段 | 返回可见错误并保留文件；禁止静默丢失凭据和配置 |
| 最早根级 API Key 迁移后仍选中豆包输入法 | 恢复原 Qwen 服务；只有 SiliconFlow Key 时使用 SenseVoice |
| 旧原子写入移动原文件后中断，启动忽略 `.json.bak` | 原文件缺失时恢复备份；损坏的原文件不被旧备份覆盖 |
| 保存到异常目录时移动了目标目录 | 先拒绝目录；写独立临时文件并使用平台原子替换 |
| 主模型 SenseVoice 残留实时标记，误用千问接口 | 按服务商能力确定传输方式，SenseVoice 使用自身 HTTP 接口 |
| localStorage 迁移未计入豆包输入法凭据 | 任意已保存的后端 ASR 凭据都会阻止旧缓存覆盖 |
| 旧 TNL 缺失新字段，自动开启口语清洗 | 保持 `off`；明确选择的新模式保留 |
| 加载时恢复了用户主动清空的预设列表，或整块重置助手配置 | 保留空预设；仅补全缺失提示词，不覆盖其他配置 |
| Qwen3 实时发送 `language: auto` 被云端拒绝 | 自动语言省略该字段；中文继续发送 `zh` |
| 选择器在连续修改后保存失败，回滚到更早的值 | 回滚到本次修改前的值 |

## 千问真实云端冒烟

使用正式 `test_api` 客户端和约 5 秒中文合成音频。所有成功结果均识别出测试句子。它验证的是接口兼容性，不代表真人、噪声、方言、长录音准确率已完成评测。

| 模型 | 模式 | 结果 |
|---|---|---|
| `qwen-audio-3.1-asr-flash` | 录音 | 成功 |
| `qwen-audio-3.0-asr-flash` | 录音 | 成功 |
| `qwen3-asr-flash` | 录音 | 成功 |
| `qwen3-asr-flash-2026-02-10` | 录音 | 成功 |
| `qwen3-asr-flash-2025-09-08` | 录音 | 成功 |
| `qwen-audio-3.1-asr-flash-message` | 实时 | 成功 |
| `qwen-audio-3.1-asr-flash-streaming` | 实时 | 成功 |
| `qwen-audio-3.0-asr-flash-streaming` | 实时 | 成功 |
| `qwen3-asr-flash-realtime-2026-02-10` | 实时 | 成功（修正自动语言参数后） |
| `qwen3-asr-flash-realtime-2025-10-27` | 实时 | 成功（修正自动语言参数后） |
| `qwen3-asr-flash-realtime` | 实时 | 账号额度阻塞，不能记为云端通过 |

最后一项的服务端返回 close code 1007，并说明免费额度已耗尽且账号开启了“仅使用免费额度”。其关闭帧超过 WebSocket 控制帧长度，常规客户端首先报协议错误；通过保留 TLS 证书验证的独立诊断确认了原始关闭原因。没有调整计费设置、放宽正式客户端的协议校验或静默切换模型。该别名保留供既有用户使用；用户可明确选择已验证的日期版本。

模型目录与协议依据见 [千问模型选择与历史配置兼容](qwen-asr-profiles.md)。
