# Windows 新增功能清理验收

日期：2026-09-28。分支：`codex/platform-integration`。依据：[功能价值审查](windows-feature-value-audit.md)。未合入 main。

## 实施结果

1. 收紧口语清理：去掉连续汉字压缩、错误起句猜测、内容词删除；旧 aggressive 枚举可读且可往返保存，运行保守规则。UI 仅显示关闭/保守。
2. 思考选项：由后端解析真实最终模型，返回当前适配已确认的选项。旧值不自动改写，旧请求映射及自定义参数优先级保留。详见 [契约](llm-reasoning.md)。
3. 个性化诊断：默认关闭，显式环境变量开启后才写文件。新目录跨天最多 200 份，写入时清理超过 7 天的本功能文件，不清理旧目录和用户历史。
4. 移除没有生产调用的 TNL/LLM pack、重复 ASR 包装函数、两个 SQLite 发音键查询入口。ASR 实际热词路径和数据库列、索引、迁移、读写不变。
5. 上下文热词默认关闭，偏好设置提供明确的实验性开关；显式开启的旧配置保持开启，关闭/开启采用字段级保存，不重置其他 TNL 参数。
6. 阶段路线图及旧 TNL 长文归档，现行文档集中描述真实运行契约。助手搜索仍是可选项，保留现有供应商和已配置用户的功能。

## 回归证据

按先失败、再实现的顺序覆盖口语误删、思考选项、诊断关闭/过期、新旧上下文配置。另修复评测门槛：替换命中率只作统计，不能要求所有测试集中至少 70% 的文本被修改；新增“正确保留原文也应通过”的测试先复现原门槛失败，再删除这一无效门槛。全量精确正确、误替换、延迟及未决候选门槛继续执行。

| 验证 | 本地 macOS 结果 |
| --- | --- |
| `cargo test --locked` | 574 项通过；8 项既有忽略项 |
| `cargo check --locked` | 通过；既有 macOS `audio_mute::is_enabled` 未使用警告 |
| `npm run test:ts` | 165 项通过 |
| `npm run build` | 通过；既有大 chunk 提示 |
| `eval_asr --suite ../tests/asr_eval` | 36/36，通过全部质量门槛，误替换 0 |
| 浏览器组件验收 | 千问/GPT/未知模型切换不触发保存；主动选择才保存；读取失败禁用并可键盘重试；上下文开关可开关、失败提示/回滚、运行时禁用；旧强力模式显示保守 |

浏览器运行实际 React 组件，使用无凭据的临时 IPC/保存模拟；不把它等同于 Tauri 全流程、真实文件写入或云端模型验收。后端真实配置解析、字段补丁与 JSON 往返由 Rust 测试覆盖。临时页面已移除。

界面检测没有发现本次新增组件的问题；两处既有删除按钮的 hover 红底被静态工具误报为灰字，实际同一 hover 状态也会切换红字，未作无关改动。新增开关复用现有 Toggle，保持页面一致性。

## 保留的验收边界

此轮没有重装用户应用、修改系统权限、迁移用户真实词库或调用带真实凭据的云服务。原配置字段、凭据和数据格式仍保留。Windows/macOS CI 负责平台编译、测试和原型打包；即使 CI 通过，也不能代替 Windows 旧版本覆盖升级、全局热键/输入或真实音频 A/B 验收。

Jieba、复杂候选及上下文热词未宣称有普遍准确率收益；需要代表性真实录音对照后才能决定进一步保留或简化。固定文本集全过不能视为新语音识别能力通过验收。
